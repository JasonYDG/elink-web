# 1.0.6 开机排版与 LED 修复整合

适用本次 DA14585 五测试点、2.13 寸黑白红 250×122 标签。管理端程序仍为1.0.3，OTA协议兼容。固件ID为 **e7d6ebb6**。

ELINK右侧同一行显示本机完整地址，不显示“MAC”标签。ELINK字号保持30，向左移动5像素；地址使用原生ASCII字模并加粗一像素。地址来自本机原生OTP缓存，未改写OTP，也没有把示例地址写死。最宽的AA:AA:AA:AA:AA:AA在250像素范围内完整显示；boot-preview.png只是第一块地址的预览。

继承Claude Code的1.0.5（24f56403）LED修复：P0_2/P2_5/P2_9设为输出高电平；在原生periph_init的0x6276处、锁存引脚之前重新配置，覆盖冷启动与休眠唤醒。该代码与保留的1.0.5二进制逐字节一致。1.0.4将低电平误认为关灯，其LED结论已撤回；请使用本版。实际灯光仍须观察，续航须测量电流。

沿用1.0.3的面板复位等待、8000字节双色层、BUSY约90秒超时清理、持续可发现及非活动应用区OTA。没有修改面板分辨率、引脚映射、LUT、原生刷新尾部或蓝牙地址。原生低电平复位等待按32MHz上限估算；实际16MHz等待更长。

选择firmware/elink-bwr-1.0.6.elink-update.json进行蓝牙OTA，完成后读状态核对e7d6ebb6。首次安装或有线恢复按FLASHING.md使用完整SPI文件，偏移0并Verify。完整SPI不能用于OTA，不操作OTP。1.0.5构建保留在原目录，不覆盖其文件或固件ID。

软件验证：28项通过，包括实际Thumb指令、五组完整地址的原生绘图与整帧比较、缓冲边界与栈、每次唤醒LED高电平、BUSY超时、双区OTA全量回读及新应用冷启动。代码与数据叠加区仍在保留RAM边界内，余量4字节；后续扩展必须重新检查，不能直接追加。实机记录见VALIDATION_REPORT.md，测试不代替24小时稳定性、物理断电OTA、电流和光学验收。
