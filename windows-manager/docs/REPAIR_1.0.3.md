# 1.0.3 面板唤醒与无按键连接修复

适用本次 DA14585 五测试点、2.13 寸黑白红 250×122 标签。

## 花屏依据

1.0.2 已完成真实蓝牙 OTA，但同一模板仍花屏。诊断固件从真实标签读取到原生尺寸122×250、每行16字节；8000字节接收RAM与主机模板逐字节一致，SHA256为d4a4895484fa193d08668dceb47ba8fb6ef3aa7bcd876b0007b75ee694955bd0。故没有用调整分辨率或替换显示波形掩盖故障。

原生初始化上电后立即将屏幕RST拉高。原生时钟在复位拉低后先绘图，自定义内容已提前收好，缺少这段隐含等待。1.0.3在共用初始化处加入上电后的低复位等待与拉高后的稳定等待；适用于开机、时钟和模板。Cortex-M0指令循环有界，在最高32MHz下分别至少约5ms与22ms；这是指令时序估算，未用示波器测量。参考同尺寸三色面板官方驱动的复位等待，并保留本标签原有LUT和SPI配置。

仅含该复位修改的测试固件a7c35efb已通过真实OTA、全量读回和版本核对。同一张“今日安排 / 欢迎使用”模板完成刷新，用户确认“文字清晰，画面正常”。最终1.0.3另合入下面的连接修改，实机记录见交付验证报告；不能用这一次观察承诺全部长期验收完成。

## 连接与故障恢复

默认持续可发现：沿用原生广播间隔和芯片在广播之间的休眠。持续广播不等于CPU与射频一直工作。连接断开后立即重新开放连接，且不触发旧时钟/二维码绘制。管理端仍提供定时接收窗口，只有主动选择才启用。

BUSY持续约90秒后关闭面板电源，恢复芯片休眠并返回错误4。显示代次不增加，管理端报告失败待核对，避免把强制清忙记成显示成功。下一次操作可重新初始化面板，无需通过BUSY强制清除假装成功。

管理端修正Windows在OTA复位时的OSError取消：仍继续重连，只有读到目标固件ID才报告升级成功。任务记录的展开回执与暂停实时更新继续保留。

## 使用

使用本包的Start.cmd，选择firmware/elink-bwr-1.0.3.elink-update.json进行蓝牙OTA；完整-spi.bin不能用于OTA。首次安装或恢复时，按FLASHING.md有线烧录完整SPI，偏移0并Verify。旧1.0.1/1.0.2仍可作为OTA入口；1.0.0已撤回。

升级后读取状态并核对firmware/manifest.json中的固件ID。在“刷新与省电”选择“持续可发现”，应用并读回验证，可覆盖此前保存的定时窗口。定制三色内容始终全刷；快速时钟模式仍属实验。

续航、电流、细字、LED和24小时运行仍按ACCEPTANCE.md实测。一次正常显示不替代这些测试。

参考：[Waveshare官方三色驱动](https://github.com/waveshareteam/e-Paper/blob/master/Arduino/epd2in13b_V4/epd2in13b_V4.cpp)，[Xiaomi硬件上的持续广播与低功耗实现](https://github.com/pvvx/ATC_MiThermometer)。后者说明可采用的产品设计，具体电流不能套用于本标签。

管理端r2复用已发现的设备对象，但每次重新获取未缓存GATT服务与真实状态。连接失败即丢弃发现缓存并重新扫描；不以缓存推断在线或固件版本。等待任务时操作按钮禁用，可去任务记录取消等待；OTA按钮需已有验证通过的升级包。
