# 1.5.8：修复离线图库第一张保存失败

本地 Windows 管理端与 DA14585 BWR 250×122 固件配套测试版。固件 ID `0ec97fc2`。

修复 1.5.7 在收完第一张 8000B 后，一条命令连续擦写整图造成长时间阻塞的实现。保存改为 32 步，每步 250B、读回并累计 CRC32；弹窗显示具体图片和保存块数。WinError 0x800704C7 显示为 Windows 中止蓝牙操作，并保留阶段，不再指称用户主动取消。实机重启原因及修复效果仍待复测。

1. 退出旧管理端，运行本包 `Start.cmd`。原 AppData/Local/ElinkManager/data 继续使用。
2. 只选择测试屏 `18:BC:5A:6B:8A:B1`，通过蓝牙 OTA 选择本包 `firmware/elink-bwr-1.5.8.elink-update.json`。
3. 读取状态，确认固件 ID `0ec97fc2` / 1.5.8。旧固件仍能普通传图；保存图库要求本版分步协议。
4. 先选两张内置图片、间隔 1 小时，点击“保存图库并开始轮播”。应依次看到上传、每张 0–31/32 块保存、提交播放列表和刷新读回，最后成功。
5. 成功后可测试四张、图片日历取景、关闭电脑后的自动换图。日历绝对日期和提醒仍需要正确校时。

上传失败时先保留任务错误与阶段，点击读取状态，再重新保存。保存中断保留已提交的旧图库；新列表发出提交但未拿到回执时仍标为结果待核对。首次初始化没有有效配置时掉电的未知区保护保持不变，不要全片擦除。

四张上限、1小时到7天间隔、内置图库、每张取景和日期设计延续1.5.7。新库保存不逐张刷屏；最后显示第一张。真实刷屏时间没有缩短，不能把包数减少等同于整次操作速度等比例提高。

应用60028B，五个C区余量162B；图库状态100B，既有尾部余量28B。原生底层代码和边界保持原字节。只提供应用OTA测试文件与1.5.5应用回退，未替用户刷机或切换正在运行的程序。

详细对比：[4.2 实现与失败定位](2026-10-18_album-upload-42-comparison.md)。此前完整功能操作见[1.5.7说明](MANAGER_1.5.7.md)，其中单命令整图保存已被本版替代。硬件速度、供电、光学、掉电和长稳仍待测试。
