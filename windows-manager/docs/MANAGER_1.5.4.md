本地版与GitHub独立网页是两个交付面。本版复用GitHub主分支提交 `2f7c6920e5efc01cae5a04cbba9e3129df30a597` 的config.json和16张原生三色像素图；不修改或发布GitHub页面。Windows继续具备原有蓝牙OTA入口；GitHub独立网页不提供OTA。

- 内置图默认展开，点击“应用到所选屏幕”，使用经过SHA256核对的8000B原生帧。
- 上传图片、裁切、旋转、原有时钟、月历和离线提醒保留。数据目录继续使用AppData/Local/ElinkManager/data。
- 日历主题增加“图片日历”：选图后居中裁切166×122，右侧年、月、大日期、星期、阴历和节气由固件绘制。主机读回合成后的实际RAM画面作为任务预览。仅固件ID d78aa415（1.5.4）启用该入口；旧版在传图前拒绝。
- 1.5.4按连接MTU选择最多128B像素包，8000B最少63包；旧固件保持17B、471包。刷屏耗时不因包数减少而消失。

## 离线轮询尚未实现

用户已明确：图片轮询和图片日历换图都必须由屏幕自动执行，电脑/手机断开后继续，间隔支持每小时、每2/3/6/12小时、每天/每2天等。两种模式共用设备图库；管理端只负责传图和保存策略。**本版没有使用Windows定时发送代替此需求。** 页面间隔控件仅展示尚不可下发的设计，已禁用，不会伪报设置成功。

当前固件1.5.4只支持一张RAM图片及单图日历。日历日期可跨天更新，但不会更换图片，断电后图片不保留。离线图库的写入、校验提交、播放列表、相对计时与掉电恢复仍待实现，不宣称完成。

## 只读硬件证据与执行空间

指定测试屏18:BC:5A:6B:8A:B1于2026-10-18已运行d78aa415。通过93/BC只读状态和Flash诊断读得原生90h返回值0xA112（厂商A1、器件12）；与复旦FM25Q04官方资料的4Mbit/512KiB身份相符。0x40000及0x7FFFC样本均FF，没有擦写、解锁或修改屏幕页面。

官方资料：[FM25Q04数据手册](https://www.fmsh.com/nvm/FM25Q04_ds_eng.pdf)，第2页容量说明、第17页表5身份、第18页指令与4KiB擦除粒度。本地证据在backup/2026-10-18/manager-1.5.4/flash-readonly-8ab1.txt；既有512KiB备份及逐块日志另已归档。只读ID不能证明图库写入、寿命、断电安全或每个原生地址的用途。

1.5.4固定C区剩余：clock30B、reminder_extra68B、product76B、reminder60B，合计234B且不连续；汇编扩展0B，保留RAM覆盖尾部152B。图库容量和执行代码容量分别核算。本轮还在隔离目录尝试同边界LTO链接，四区体积与原构建完全一致；既有字形表尾部合计仅120B，未借此移动任何边界。新增图库代码必须先通过安全布局与边界验证，不占用启动、射频、屏幕驱动、校准、提醒区或OTA回退区。
