# 管理端 1.5.12：连接准备与服务发现恢复

本版只更新 Windows 管理端，配套固件仍为 **1.5.10 / fde89808**，不需要为本次连接处理重刷屏幕。

用户报告旧屏时而可读、时而出现“设备没有 HMCLOCK FF01 控制特征”。现场同一设备在失败后，经只读诊断确认 FF00/FF01 均存在，FF01 可以返回数据；不能凭首次服务列表缺项断言设备永久缺少接口。Windows 返回不完整服务列表的具体驱动或链路原因仍未确定。

管理端现在区分连接与控制接口就绪：连接后必须发现 FF01 才发送命令。若首次服务表缺项，释放当前连接，重新发现，最多三次。仍失败时停止并显示本次真实服务 UUID，避免用“设备没有接口”作确定诊断。初始连接、图库提交后的只读核对、OTA 重启后的版本核对共用这一步骤；不会重发图库提交或 OTA 启动标记。

若扫描未找到广播，但 Windows 仍持有已连接的设备，核对系统返回的完整 MAC 和连接状态后，继续发现其 GATT 服务。此路径仍须通过 FF01 与状态检查，不把缓存名称或缓存记录当作新广播。Windows 对象在读取后关闭，未连接或地址不匹配时保持失败，不尝试其他屏幕。

手动任务遇到未广播、连接或超时错误，最多三次后停止、解除任务锁。定时计划和离线提醒安装仍保留原有接收窗口策略；提交后的不确定结果保持“结果待核对”，不自动重放。等待状态改为“等待设备连接”。

4.2 寸方案的实际代码对照、现场证据和验证边界见 [通信对照报告](2026-10-19_ble-42-comparison-report.md)。本次采用的是连接准备分阶段确认、失败释放与有界恢复，不复制对方的底层驱动、句柄、授权或固定 MTU。

## 使用

退出旧管理端后启动本包 `Start.cmd`，确认版本 1.5.12。原 `%LOCALAPPDATA%/ElinkManager/data` 继续保留。先读状态，观察接口发现的重试和最终回执；屏幕已有固件与图库无需重写。

软件回归使用模拟故障和真实旧版指令验证恢复边界；无法保证已消除 Windows/适配器的所有偶发问题。长时间重连、现场通信和光学结果分别记录，不以测试通过替代验收。
