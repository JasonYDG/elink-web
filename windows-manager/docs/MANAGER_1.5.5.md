# Windows 管理端 1.5.5 / 固件 1.5.5 测试版

本版为单图图片日历、图库选择、取景和操作反馈的配套更新。**屏幕持久图库与离线多图轮换仍未实现**，不能以 Windows 定时发送代替，也不能把日期跨天更新称为图片轮换。

## 使用顺序

1. 退出旧管理程序，运行本包 Start.cmd。沿用 AppData/Local/ElinkManager/data；不迁移或清空设备、图片、提醒及历史记录。
2. 选择屏幕并读取状态。用“蓝牙固件升级”选择 `firmware/elink-bwr-1.5.5.elink-update.json`；完成后再读取状态，固件 ID 为 `6c3279f4`。
3. 选择“图片”，或“日历 → 图片日历”。内置16图紧接功能配置；点图只选择，应用按钮统一发送。自有图片仍可上传、缩放、旋转、保存。
4. 图片日历可在预览上左右拖动，或用滑杆/靠左/居中/靠右按钮；在原生250列中选取166列，不重采样。每张图的位置由当前浏览器保存，发送时固定进该任务快照。
5. 操作期间出现最上层进度弹窗。传输100%不等于刷新结束；等待完成回执后自动关闭。失败或结果未知保留弹窗，需核对后关闭。等待任务可以取消。

日期列按年/月、红色大日期、星期、农历、节气、倒计时排列。2026-10-18显示“霜降 / 5天后”，节气当天显示“霜降 / 今日”。采用原固件节气日算法及农历表；预览与实际编译代码逐字节比较，覆盖节气当天、两位数倒计时、跨年、闰月、闰日。1.5.4保留协议兼容，管理端新的图片日历入口要求1.5.5以确保排版和一次提交行为相符。

## 传输与4.2对照

复核同一GCLab APK SHA256 a651bfb07f5980d5e5cbaba9445237cf2d7bf6b4419a3127493e8d0928a6cf84及OM6626原固件6fcedbb08bc39361a29b15e3ad22cbdd9d5907ed7f54b15d9405c5a2f81bd7ca，并从原arm64库重新解析验证65条MTU、传输进度、存储相关字符串。字符串证明存在这些设置/反馈线索，不能证明其具体写入窗口或实测速度。

已落实：连接准备/能力识别、按真实MTU及固件能力分包、先预览再统一发送、完成状态与传输进度分离、失败回执、图片日历减少一次完整显示事务。每次回执保存ATT MTU、包长、包数及准备/传输/刷新/读回耗时，任务记录显示后三段时间。旧设备保持17B；已支持的大包最多128B（8000B需要63包）。

原路径图片先提交97刷新，再9C03合成日历刷新；新版收到完整8000B且校验和一致后，可直接9C03合成刷新。丢失提交回执仍按结果未知处理，不自动重复提交。校验、BUSY结束、显示代次和最后RAM读回均保留。单图图片原路径不变。

现有本机图片日历记录约58.7秒，128B已生效；历史记录没有分阶段计时，不能据此断言蓝牙、LED或面板各耗时多少。减少显示事务已由实际Thumb代码验证，实际快多少仍需同一设备对比。未改蓝牙驱动、连接参数、LED底层或面板波形，没有通过缩短波形等待来提速。

## 空间与保护边界

本版四C区剩26/16/76/44B，合计162B且不连续。这只统计当前固定C区，不是整个芯片的剩余容量，也不是轮播无法实现的证明；另有字库尾部225B及RAM扩展尾部152B尚未纳入可执行区，详见[容量复核](2026-10-18_album-capacity-audit.md)。静态模块结构、原地址和上限均保持；为补齐小字“天后”，只移除该字号没有调用的ASCII字形，保留MAC、版本、电量和全部中文标签。

新增差异仅在已验证的应用UI代码、小字库、固件ID范围。启动/复位、原生蓝牙、面板、SPI驱动、OTA/广播/引脚辅助代码与1.5.4逐字节一致；Flash启动区、提醒区、面板配置区等非应用区一致。不提供整片擦除、全SPI覆盖或图库格式化入口。

物理Flash型号与512KiB相符，并有用户全片导出；这些不等同于已完成高区所有权、原子提交/相对计时、断电恢复及运行空间验证。离线轮换尚未完成；下一步需测量复用提醒存储代码、应用层消重及重新链接的实际成本。按YDG硬件保护要求，在这些检查通过前保持写入入口关闭。没有悄悄占用提醒槽或OTA回退区。

固件和Windows包分别构建、校验并保持独立回退；实际运行版本与已打包版本须分别检查。本轮不自动连接或烧写屏幕。
