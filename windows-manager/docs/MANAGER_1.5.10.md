## 本次现场核对

84:BA的1.5.8 OTA已取得ota_boot_verified。8A:B1的图库操作在BD03提交回执处断连，但随后状态返回：4张、60分钟、sequence=2、running=true、index=0、writing=false、error=0；所有图片CRC和取景与任务快照一致。独立只读取得8000B像素，与所选第一张逐字节一致。因此该次四张图库已经提交，旧任务当时没有取得完整确认。历史任务保持原记录，不伪造为当时已取得回执。

1.5.10提交BD03最多一次。连接中断后只重连读取，核对新序号、四张CRC、取景、间隔、模式、完成代次及首图像素；不重复上传或重发提交。未匹配仍为结果待核对。图片块保存失败继续停止，不自动重复擦写。

“读取状态”现在会在设备空闲、无错误时读回完整像素，卡片标为“设备像素读回”。读到不同代次/模式/传输标识时不使用该图；读图失败保留已读状态并说明原因。该图是设备显存快照，不等于相机拍摄或光学验收。完整读回需要额外等待。

新的操作单独计时、单独收集任务结果，不把前一次错误和累计时间带入后续成功OTA弹窗。

## 固件计时修复

实机校时后，原分钟回调会保留秒数，例如09:07:37到09:08:37。1.5.8应用错误地只在秒数等于0时累计轮播分钟，导致已启用的图库不换图。1.5.9去除该应用层限制；保持原分钟回调、底层时钟、蓝牙和休眠基础不变。新增测试从原0x25C0入口执行，验证非零秒的完整60分钟后切到下一张；未校时及掉电恢复测试继续保留。

应用五个固定C段余量198B，仍分散；图库状态100B，既有尾部余量28B。底层保护、双配置页及双图像区保持。旧图库格式不变，升级后仍可读取已提交的图片。

## 测试步骤

1. 退出旧管理端，运行本包Start.cmd，网页版本应为V1.5.10。
2. 先给一块测试屏OTA升级本包firmware/elink-bwr-1.5.9.elink-update.json，读状态确认b826f754。
3. 点击读取状态，等待“设备像素读回”预览。旧四张图库仍在时无需为了恢复预览重复上传。
4. 设置一次图片与间隔，在整屏图片和图片日历之间切换；相同图片应显示复用图库。可关闭电脑验证定时换图，图片日历先完成校时。
