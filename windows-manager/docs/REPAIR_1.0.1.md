# 1.0.1 冷启动修复与独立开机页

1.0.0 已撤回，不应再次刷入。此修复包仍是实机验收候选，不把指令执行测试当作射频、供电或面板实测。

## 已确认的原因

用户烧录 `elink-bwr-1.0.0-spi.bin` 后，Toolbox 日志显示完整 SPI Verify 通过；重新上电后没有可用蓝牙广播。原版应用的 scatter 表首项位于文件 0xDBE4，内容为 `[0x07FC0110, 0x07FC0110, 0x400, 0x07FC7088]`。实际执行 0x07FC1F90 的原生初始化函数，会把 0x07FC0110..0x07FC0510 清零。SDK 配置把这 1024 字节定义为 TRNG 缓冲区，前面的 0x07FC00C0..0x07FC0110 是 ROM 补丁表。

1.0.0 在该区域放置常驻扩展和状态，布局判断错误。之前只执行扩展函数的测试漏掉了原生冷启动。1.0.1 的所有指令测试先执行真正的启动入口、硬件初始化指令和 scatter 初始化，再进入扩展；另模拟 TRNG、补丁表、原生非保留堆全部被写入，验证扩展仍完整。

## 最小布局修复

- 原版应用、初始化表、栈、2048 字节非保留堆、保留数据和面板缓冲的地址不移动。
- 附加负载存放在应用文件末尾；复位入口先将它复制到 0x07FD1480 起的保留 RAM 空隙，再进入原版复位路径。复制入口临时位于 0x07FC0110，此时 TRNG 尚未初始化；入口执行完毕后，该区继续按原版方式清零和使用。
- 原生非保留堆为 0x07FD0C18..0x07FD1424（含12字节头），保留数据从0x07FD21C0起。构建器对这两个边界及复制大小强制校验，越界即停止。
- 状态在0x07FD1980，应用文件对应0xE2D4。双区应用长度和CRC均重新计算。1.0.1应用60068字节，完整SPI仍241664字节；无线协议继续使用16位长度。

## 自己的开机画面

`firmware/boot-preview.png` 是实际传给屏幕的黑白红二值像素预览。画面由本地代码自行绘制：ELINK、BWR 2.13 / 250x122、主版本号和 BLE CONTROL，无作者二维码。压缩数据经实际 Thumb 解码测试还原为两个4000字节面板缓冲；刷新与休眠收尾沿用原版启动页流程。

广播名称改为 `ELINK-BWR-732dfd`，蓝牙 MAC 不变。管理端需要同步更新到1.0.1，旧管理端的升级包校验位置不适用于新布局。

## 安装和验收

本次须有线写入1.0.1完整SPI镜像，偏移0，并完成Verify；当前1.0.0不能作为可靠OTA入口。关闭烧录软件、断开全部供电后重新上电，观察ELINK开机页，再扫描 `ELINK-BWR-732dfd`。在1.0.1管理端读取状态，固件标识必须与清单一致。操作失败时保留日志，使用包内 `rollback/hmclock-bwr-baseline-spi.bin` 恢复已验证三色基线。

真实连续连接、LED、耗电、显示波形、广播窗口、断电恢复及跨版本蓝牙OTA仍须按 `ACCEPTANCE.md` 实测。
