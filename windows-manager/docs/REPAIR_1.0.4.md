# 1.0.4 本机地址与 LED 修改（历史版本）

本版LED极性判断错误，用户观察到灯持续亮，勿用于关灯修复。1.0.5已经改为输出高电平，并补齐每次唤醒配置；当前交付见REPAIR_1.0.6.md。

适用 DA14585 五测试点、2.13 寸黑白红250×122标签，延续1.0.3的复位等待、BUSY超时和持续可发现模式。

开机页在ELINK下方显示完整MAC，读取原生启动已经缓存的本机OTP地址，不在镜像中写死同一个地址。两块标签应分别显示18:BC:5A:6B:91:A7与18:BC:5A:6B:8E:BF。MAC使用原生ASCII字体，加一像素粗描边。boot-preview.png仅为第一块地址的预览示例。

pinout_0.xlsx确认P0_2为红灯、P2_5为绿灯、P2_9为蓝灯。本版曾把三路输出低电平误认为关灯，实际上用户观察到常亮。后续分析还发现每次唤醒会重置未配置的引脚。三路引脚应在显示入口及唤醒锁存前设为输出高电平；该修复由1.0.5完成。灯无需常亮来保持蓝牙广播；电池续航仍需电流测量。

已有1.0.3可直接在本机管理端选择firmware/elink-bwr-1.0.4.elink-update.json进行OTA。首次安装或有线恢复使用elink-bwr-1.0.4-spi.bin，偏移0并Verify。不要把完整SPI文件选进OTA，也不操作OTP。管理端程序仍为1.0.3，其连接与OTA接口兼容本版固件。

读取固件ID应为768fcd19。第一块已经通过实际OTA全量读回和新ID核对；第二块保留1.0.3，用户可自行升级。实际开机像素和LED观察结果见交付验证报告；24小时稳定性、实际电流和物理断电OTA测试不以软件回执代替。

旧disasm2_hooks.py的Thumb LDR常量偏移曾误取指令高字节；现改为低8位乘4并检查LDR literal编码。0x40f4是寄存器加载，不能解读为PC常量。已核对disasm4_commit_path.txt及基线字节；旧错误输出不作为补丁地址证据。
