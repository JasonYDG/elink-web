# 1.5.7离线图库实现与边界

2026-10-18。固件ID `c028427e`，应用60028B，RAM扩展装载3240B。图片和图片日历共用一套最多4张图库；设备按60–10080分钟切换，管理端提供1–168个整小时。四个原功能模块不变，图库属于image模块。这里记录实际实现，实机光学、续航、掉电时序与长稳尚未验收。

## 存储与提交

所有区间为左闭右开。低256KiB、日程、双应用槽、产品/面板数据均不分配给图库。原生SPI型号读取返回A1/12才启用；没有有效配置时，必须检查专用72KiB每个字节都是FF才能初始化。

| Flash范围 | 大小 | 用途 |
|---|---:|---|
| 0x40000–0x41000 | 4KiB | 配置页0 |
| 0x41000–0x42000 | 4KiB | 配置页1 |
| 0x42000–0x4A000 | 32KiB | 图像区0：4个8KiB槽 |
| 0x4A000–0x52000 | 32KiB | 图像区1：4个8KiB槽 |
| 0x52000–0x80000 | 184KiB | 本版本不使用 |

每槽保存8000B原生黑红像素，192B对齐填充。不保存或解码JPEG；各张共用已有4000B黑层和4000B红层RAM缓冲。先写非活动图像区，逐张CRC32读回；提交前再次检查整套帧CRC。配置交替写另一个页，核对读回CRC及序号确实等于本次配置，最后单字节写入ready=FE。读取两个有效页时选择最新序号（按32位回绕比较）。普通播放不擦写Flash。

旧图库存在时，替换中断保留完整旧图库或完整新图库；不能将部分新图当作提交成功。首次空配置尚未形成有效页就掉电，可能留下未知非空内容，后续会拒绝自动初始化；须读回评估，不能自动清空或整片擦除。Flash写失败、帧CRC错误、型号不符均有失败状态。

## 配置与协议

新增`BD`命令，保留现有校时、传图、提醒、OTA接口；能力查询`ELUI`第6字节bit2表示支持图库，管理端还检查实际Flash诊断。不了解此扩展的旧客户端仍可普通传图；若要永久停止已保存的轮播，应先发送BD04。旧客户端只换页面会在本轮停止，完全断电后已启用的图库仍可能恢复。

| 命令 | 内容与行为 |
|---|---|
| BD 00 | 返回52B ELA1图库状态 |
| BD 01 | 检查/初始化专用分区，开始非活动图像区事务 |
| 95 / 96 | 原上传开始/像素协议，8000B，最大128B像素载荷；此时不发送97 |
| BD 02 slot crop crc32 | 8B命令；slot从0连续递增至3，crop=0..84；校验RAM并写Flash，再读回CRC |
| BD 03 mode minutesLE16 | 5B命令；mode=0整图，1图片日历；提交并显示第一张。无新上传事务时更新已有图库的模式和间隔 |
| BD 04 | 持久停止轮播，保留图片数据；须读回确认 |

40B配置：magic(4)、sequence(4)、crc(4)、minutes(2)、count(1)、mode(1)、frameCRC[4](16)、crop[4](4)、bank(1)、enabled(1)、ready(1)、pad(1)。所有多字节值小端。配置CRC32覆盖0..7与12..37字节，排除CRC字段和最后两个字节。`ELA1`状态前12B为标识、版本、是否有配置、运行状态、当前索引、上传状态、暂存数量、已计分钟，后40B为当前配置。

管理端在队列接收时冻结原始帧与每张取景位置。上传每张核对接收偏移和暂存数量；提交后核对CRC列表、间隔、模式、取景位置、显示代数并读取首张实际RAM像素。提交回应丢失记为“结果待核对”，不自动重发整个提交。界面顶层弹窗把多个屏幕动作串行展示，执行期间锁住冲突操作。

## 定时与页面互斥

应用分钟钩子仍先调用原生clock_print，再累加相对分钟；不修改SDK计时或蓝牙入口。未校时也能切图。BUSY、OTA、活动提醒期间暂停；写入事务5分钟无完成会释放暂存状态，下一个节拍恢复已提交图库。单图不会按间隔重复刷屏。

冷启动由已有应用开机回调初始化96B图库状态，从第一张重计；未校时的图片日历只显示左侧图片，日期栏留白。管理端校时后重新启动该图库第一张，恢复日期。照片日历每天更新右栏；提醒优先，有持续时间的提醒结束后恢复同一张图片并重新计间隔。停止轮播、切到时钟/月历/任务汇总/默认页/普通单图均经管理端持久停止。

## 空间与底层证明

原66px时钟字库3820B槽内，3819B数据无损编码为1248B；原0..9和冒号逐像素保持一致。空出的2572B成为`.album`，包含共用字体解码器。44px日历数字为独立原生尺寸字形，不再3倍放大15px字。字形来自仓库内SIL OFL许可的Noto Sans SC，未复制4.2专有字库。

| C区段 | 使用/容量 | 余量 |
|---|---:|---:|
| .clock | 1166/1284B | 118B |
| .reminder_extra | 2716/2724B | 8B |
| .product | 4432/4460B | 28B |
| .reminder | 2200/2208B | 8B |
| .album | 2536/2572B | 36B |

合计余量198B仍分散。图像Flash多与少不等于可执行代码余量。96B状态在既有0x07FD2140..0x07FD21A0，未扩大0x07FD21C0原生边界、栈、堆或ROM蓝牙区。完整范围见 [DEVICE_MEMORY_MAP.md](DEVICE_MEMORY_MAP.md)。

`test_photo_calendar_155.py`逐字节比较1.5.5和本版，仅允许明确应用/字体段、7处4B应用调用地址、能力表地址及版本标识改变。原启动复位、BLE/射频、SPI驱动、面板驱动与波形、CRC表及OTA原代码均相同。`test_offline_album.py`另执行原生SPI读/写/擦指令，硬件总线边界取样证实高地址字节没有截断。OTA包仅含应用升级JSON，不含全片覆盖镜像；图库首次实际保存才会写上述高区。

## 验证材料

本轮工作区证据在`backup/2026-10-18/offline-album-1.5.7`，配套包另带最终测试记录、保护区比较、空间表和字体许可。

- 真实编译Thumb执行：4张顺序/回绕、全天1440分钟边界、断开主机计时、冷启动未校时恢复、提醒恢复、BUSY/OTA暂停、CRC损坏停止。
- NOR模型故障注入：未知区拒绝、错误芯片拒绝、提交各阶段掉电、写入失败后旧有效配置不能冒充新配置；所有图库擦写地址限于72KiB。
- 实际管理端到编译固件链路：冻结图像、63包/张、校时保持轮播、配置/像素读回、停止、提交丢回执。
- 字体和日期：所有31天数字、当天节气/倒计时/闰月/跨年逐字节主机与固件对照；四个时钟整帧与1.5.6相同。

以上不能证明真实Flash写入耐久、电池中断时序、蓝牙吞吐、刷屏光学效果或长期计时精度。实体测试应先使用已指定的18:BC:5A:6B:8A:B1，再推广到其他屏幕。
