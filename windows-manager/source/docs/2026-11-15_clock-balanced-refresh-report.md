# 1.5.23：平衡/加深笔画局刷与忙状态恢复

用户反馈本轮很可能安装1.5.22：不要“每次全刷”选项；原第二项笔画逐渐变粗；原第三项边框闪浅灰、新笔画仍略浅。随后切月历报设备错误2，读取状态报“提醒存储返回无效”；用户拔电池后恢复连接并回到初始页。本轮没有通过蓝牙读回安装版本，也没有连接或写入设备。断电恢复是用户观察，尚不能确定现场异常的唯一原因。

## 笔画通道

1.5.22的原生边框寄存器仍为5，其低两位选择LUT1。原白色笔画脉冲也在LUT1，故仅屏蔽像素不能屏蔽边框。对旧版编译程序执行的新增回归先失败：边框选中的通道首字节为128，而非中性0。依据为本机固定HMCLOCK源码及Good Display的IL3897资料第12、29页；硬件边界仍为模拟，未证明实际边缘显影的全部成因。

1.5.23只在现有应用刷新路径中调整两个临时发送平面的编码：变化黑笔画选LUT0，变化白笔画选LUT2，未变化像素选LUT1。把原FAST白色向量原样映射到LUT2，LUT1和LUT3中性。因此原生边框5无需改寄存器便跟随中性通道。应用持有的目标黑白/红平面保持，完成后清空临时遮罩。原扫描范围、原生初始化、驱动和原始波形数据、脉冲时长、重复数、供电及频率参数不改；没有增加新校准值或改写OTP。

旧的单向FLY直接擦写不再作为独立选项。模式1先使用原有FAST平衡擦写处理变化笔画，以改善残留逐步积累的问题；它没有改变字体掩模或做字形加粗。模式2完成相同平衡过程后，只对新出现的黑笔画再执行一次原有FLY黑色脉冲过程，避开未变化笔画、白底和边框通道。不是对分钟矩形、整个数字或全屏补黑。实际粗细、深度和边缘是否满意仍待实屏复验。

模式2两个阶段共用已捕获的目标分钟和目标帧；第二阶段仍BUSY、尚未提交显示代次。只有全部成功才提交一次代次和分钟参考。任一阶段超时均不提交参考，下一次恢复用现有完整刷新流程。保留首次显示、小时/日期/外围内容变化和周期维护清理。

## 网页忙状态与无效回执

设备错误2表示命令被忙状态拒绝。旧网页idle()把历史错误2直接视为永久失败；读取B4/BB时若时钟恰好开始刷新，固件拒绝请求且没有发布新的提醒响应，网页可能拿到上一条响应，快速重试后报解析失败。新增网页模型复现这两种失败，以及切页在预先检查空闲后又撞上刷新的竞态。实际现场没有原始返回字节，因此这些是已复现的软件缺陷，不能把全部现场现象归结于同一原因。

现在空闲等待允许继续观察错误2，保留95/190秒超时边界，其他错误仍失败。查询解析失败后先重新读取状态、等屏幕空闲，然后按既有最多3次界限重新发送只读请求。B4返回还需对应请求槽号；真正的坏数据继续报错，附带指令、长度和最多32字节原始回执。不会用默认提醒、假画面或清空存储代替失败。

默认/时钟/月历共用的切页路径，只有明确读到错误2且视图未发生其他变化时才等空闲重试，最多3次。已接受的切页不重复提交；传图、图库提交、提醒写入及OTA没有增加自动重放。没有新增后台连接循环、设备复位或擦除。
