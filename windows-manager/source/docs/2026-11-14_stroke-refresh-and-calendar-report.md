# 1.5.21：笔画差分局刷、六行月历与统一字形

本次依据用户的真机反馈：分钟区域出现浅灰矩形，旧数字残影逐渐累积；图片日历大红日期有明显大像素格。继续保留真正的点阵字库，所有核对图均以250×122实际可见像素输出，不使用Computer Use。

## 月份确实可能跨六行

周日为首列时，行数为`ceil((首日星期偏移+当月天数)/7)`。2026年5月和8月需要六行；2026年11月需要五行。用户提供的Windows日历以周一开头，因此该月跨六行。六行是月历覆盖六个周行，不是一个月有42天。

旧实现已在首日偏移加天数超过35时采用六行。新版将普通/六行日期统一为12点字格、11点墨迹；五行15点行距、六行13点行距。末行起点109，字形墨迹止于119，红色今日背景止于121，均在0..121内。384个支持月份检查行数范围；实际编译用例包含2026-05、2026-08、2025-03、2027-05的最后一天及闰年、四行、五行日期。星期改为白底文字，周末保留红字，增加留白。

## 针对灰框改刷新范围

旧分钟局刷将逻辑x138..240、y24..95整块区域设为可驱动，包含7416个像素，空白背景也在其中。旧整页轻快模式没有笔画遮罩。源码缺陷与用户灰框现象一致，但软件不能证明唯一光学原因。

新版在两种快刷模式下，都用实际LCD编译字表解码上次成功分钟与本次目标分钟，异或得到变化笔画。控制器R层中，变化像素为0、其他为1；保持原有中性组合和FLY/FAST波形。原生驱动函数、初始化和波形表未修改。窗口选择沿用已验证的分钟局刷参数；应用新增笔画遮罩。

目标BW缓冲不改写。时钟原本为空的RR缓冲只临时用于异或，逐行发送后恢复为空；读回仍为真实目标红层。上次成功分钟复用原32字节UI状态中的未用字段。绘图前锁定分钟，数字和遮罩共同使用该快照；注入绘图期间计时推进的用例已先失败、修后通过。时钟pending编码为目标分钟+1，0继续表示空闲，避免BUSY跨分钟后提交错误时间；失败不提交参考。首次、整点、日期、外围内容变化、周期全刷及切出时钟的白色清屏/目标双阶段保留。

交付固件06:55→06:56的真实SPI记录为128个驱动像素，未变化笔画、字腔及背景均保持中性。这是像素数量，不能据此推算刷新耗时、耗电或墨水显影质量。

本地4.2寸`source/firmware/app/calendar_controller.c`按屏型选择上一帧/当前帧处理，并每60次或换日全刷。可复用其保留参考和周期维护原则。本机可隔5分钟刷新、跳过更新或BUSY失败，所以采用上次成功分钟，而不按当前时间减60秒推测前帧。4.2寸控制器的波形、寄存器及驱动未移植。

## 文字与图片大日期

以用户提供的Windows日历截图为版式参考，采用清晰层级、白底星期和更宽松间距。CLI只读确认本机有Segoe UI/微软雅黑字体；设备继续使用原生点阵来源。

90个原生18px汉字统一为Unifont16骨架，字格不变。增重保留源墨迹、八邻接分离笔段、四邻接白色区域和原字腔；能补实的对角连接继续补实，不把复杂字全部叠粗。兔、猴保留源字形必要的对角连接，未添加断笔或合并分离笔段。24节气27字与1.5.20逐字节相同。来源和固定90字在`source/fonts/ui-cjk-18.json`，可用`source/tools/build_ui_fonts.py`重现。

图片日历44点字格内的大红日期，改用同一固定版本原生Terminus32 Bold骨架，取代原8行数字四倍放大。墨迹20×32、步进27、位置不变；使用最近邻映射，无灰度或浏览器字体。0使用同字库O的点阵轮廓，去掉终端式斜杠。原始BDF不改动，归档和原文件SHA均校验。图片左侧174列原图、取景和已有图库不变。已存公告/提醒需要重新保存下发，才会替换相应用字。
