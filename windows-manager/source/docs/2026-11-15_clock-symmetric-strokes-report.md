# 1.5.24：连续局刷补擦对称与空闲回调保护

本轮按刚交付1.5.23/40059a32及两种新选项排查，未通过蓝牙读回现场版本。用户观察：平衡模式新数字偏浅、旧笔画留轮廓；加深模式第一次变化很好，第二次开始新笔画过粗、消失笔画轮廓明显。没有连接或刷写设备，也没有使用Computer Use。

## 已定位的软件不对称

1.5.23两种模式第一阶段都用原生FAST平衡程序。加深模式第二阶段只对新增黑墨迹执行原生FLY黑脉冲，消失笔画没有对应补擦。若已补黑的笔画下一步消失，额外黑驱动没有相应白驱动。因此单次新增笔画看起来好，不能证明之后的擦除路径也正确。此前不少用例每次新建模拟器，单步检查无法替代连续往返检查。

本轮直接执行原生初始化0x07fc3F68和完整画面装载0x07fc40E8，输入05→06→05→06。旧版第二阶段黑向量为原生黑脉冲，白向量为0；每步的数字源电平帧计数为黑+30、白0。补擦后的对应计数为黑+30、白-30，原黑脉冲强度保留。这里的正负帧数只是按IL3897格式解码的数字计数，不是电荷、温度补偿、墨水密度或残影模型，不能据此宣称实屏零残影。

1.5.24加深模式仍先做原生FAST平衡擦写，第二阶段对新增黑笔画补黑、消失笔画补擦白；两类脉冲均原样复用原生FLY向量及其参数。两个发送平面始终按原始新旧字形XOR编码，未变化笔画、白底和边框LUT1仍中性。没有给整块分钟矩形、完整数字或未变笔画反复加黑，也没有通过加粗字体来遮住残影。

平衡模式增加一次原生FAST平衡擦写，黑白两类变化笔画一起轻度补偿。没有发明更高电压、改变脉冲宽度或引入其他屏型的参数。改善浅字和旧轮廓是此候选的实测目标，重复平衡流程是否足够仍需真机比较，不能由1bit预览证明黑度变化。

## 独立复现的异常回调

还复现一条确定的软件异常路径：补偿超时后pending已清零，而partial仍保留；主机成功设置清掉错误4后，遗留空闲回调可能再次进入补偿。新增回归先在旧逻辑失败。现在补偿入口同时要求pending非零，不能在没有待处理画面时重新启动刷新。两个阶段全部成功后才提交一次显示代次、分钟参考和清理计数，任何阶段失败都不提交。此缺陷与现场轮廓问题的关联尚未唯一确认。

## 连续验证与保留范围

新增两种模式的05→06→05→08→09→08→05连续检查，核对每次两个阶段的真实发送平面、白/黑向量、边框中性、单次代次提交以及回到原数字后的源电平帧计数配对。包括8→9这种只消失笔画的情况。另执行实际原生初始化/完整RAM装载，逐字节核对每个重装载目标；模拟ROM、SPI/BUSY硬件边界，不把这些边界假定为真实屏显影。

原生驱动执行比原先应用测试需要更大的指令上限；原测试run()的100万指令预算不适用于真实装载路径。本轮专用测试使用明确的800万上限，要求停在已知返回/协议边界并检查栈恢复，不把提前停止当完成。最初的探针失败记录保留，之后的有效前后对照均完整返回。加入空闲回调保护前的24草稿已中断并归档，未发布。

边框寄存器保持原生5，LUT1中性；原生初始化、扫描、驱动、无线、供电/频率、原始波形表及参数、设备身份/校准、Flash存储和堆栈边界保持。源字库、24节气和布局不变。继续保留首次显示、小时/日期/外围内容改变及周期清理；没有恢复“每次全刷”选项。1.5.23网页忙状态恢复、只读查询/槽位校验及受限切页重试继续保留，图库/提醒/OTA没有新增自动重放。

所有PNG由最终编译应用RAM逐位解码为250×122，无浏览器绘字、缩放、抗锯齿或补画。连续帧只展示目标像素，不渲染“更黑”的假效果；红色补黑/补擦遮罩和字形拼表是标记清楚的诊断图，不是设备页面。
